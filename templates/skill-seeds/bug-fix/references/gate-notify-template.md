# 闸门京 ME 消息提醒模板

开确认闸门时，对话内展示确认内容的同时，用 `jm-notify` 给**当前操作用户**发一条个人消息（用户可能不在对话页）。

确认闸门名称：**Bug列表** / **Bug确认** / **Bug原因** / **修复方案** / **建分支确认** / **提交确认** / **推送确认** / **行云部署** / **流程切换** / **服务评价**

## 发送规则

| 项 | 约定 |
|----|------|
| 收件人 | 当前操作用户 ERP：`OPT_ERP` > `ERP` > `USER` > `jm-notify` 配置默认 erp；仍未知则先短问一次 |
| 时机 | **每次**打开确认闸门（含同闸门再次确认）时同步发送 |
| 是否再确认 | 发给自己的闸门提醒 **无需** 再问「要不要发」 |
| 与缺字段通知区别 | `--notify-missing` 发给 **发起人**，正式发送前仍须用户确认 |
| 失败策略 | 发送失败只在对话里一句话说明，**不阻塞**闸门等待 |
| 通道 | `jm-notify`：见下方「Agent 调用示例」（**禁止**用 `../jm-notify`，cwd 通常是业务项目根） |

## 文案原则

- 友好、短、可行动（像同事提醒，不是系统冷通知）
- 必须含：当前节点、要做什么、可选操作、**去回复深链**（写入京 ME 正文）
- 控制在约 8～15 行，避免把整份根因/方案原文贴进京 ME
- 详细内容以对话页闸门展示为准，消息里给摘要 + 深链跳回任务窗口

## 通用骨架

```text
🔔 Bug 修复提醒 · {闸门名称}

嗨，需要你回一下确认～（你可能不在对话页）

📍 当前节点：{节点名称}
🐛 相关 Bug：{编号/标题摘要，未知可省略}
👉 请你：{一句话说明要确认什么}

可选操作：
{1～4 条选项，每条一行}

回复方式：点击下方链接回到任务窗口回复（如「确认」「选 2」「先暂停」）
👉 去回复：{REPLY_URL}
```

> **硬性要求**：`{REPLY_URL}` 必须来自执行 prompt 中注入的 `👉 去回复:http://.../?log=...` **原样写入京 ME 正文**（`--content-file` / heredoc 里）。  
> 禁止只写在对话闸门展示、却漏进京 ME。若执行环境未注入深链，才退回「回到对话里直接回复即可」。

## 分闸门文案示例

### 闸门「Bug列表」· 锁定目标 Bug

```text
🔔 Bug 修复提醒 · Bug列表

嗨，需要你回一下确认～（你可能不在对话页）

📍 当前节点：锁定要处理的目标 Bug
👉 请你：选定或确认准备处理的那一条

可选操作：
1. 确认处理拟选中的 Bug
2. 回复编号/序号，换另一条
3. 先不修 / 暂停

回复方式：点击下方链接回到任务窗口回复
👉 去回复：{REPLY_URL}
```

## Agent 调用示例

在**业务项目根目录**执行（JoyCode/Cursor 默认 cwd）。先解析 `jm-notify` 目录，再用绝对路径调脚本；**禁止**写 `../jm-notify/...`（会指到项目外）。

```bash
# 优先全局安装；否则用当前项目 .joycode/skills
JM_NOTIFY="${JM_NOTIFY_DIR:-$HOME/.joycode/skills/jm-notify}"
[ -d "$JM_NOTIFY" ] || JM_NOTIFY=".joycode/skills/jm-notify"
[ -f "$JM_NOTIFY/scripts/send_joyme.py" ] || { echo "jm-notify skill 未找到: $JM_NOTIFY"; exit 1; }

cat <<'EOF' | python3 "$JM_NOTIFY/scripts/send_joyme.py" --mode user --erp "$OPT_ERP" --content-file -
🔔 Bug 修复提醒 · Bug列表
...
EOF
```

发送成功后，对话里可附一句「已通过京 ME 提醒你」；失败则「京 ME 提醒发送失败：{原因}，请直接在对话回复」。
