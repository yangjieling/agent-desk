# 命名与代码风格规范

> 本规则定义命名、格式和代码结构基线，示例以 Java 为主。其他语言（Go/Node/Python/Rust）请按语言社区惯例适当调整。团队可根据实际技术栈补充或覆盖。

---

## 1. 命名风格

- 类名使用 **UpperCamelCase**；方法名、变量名使用 **lowerCamelCase**；常量全大写下划线分隔（`MAX_COUNT`）。
- 抽象类以 `Abstract` 或 `Base` 开头；异常类以 `Exception` 结尾；测试类以 `Test` 结尾。
- 禁止使用拼音命名、无意义缩写、魔法值（未定义常量的硬编码字面量）。

## 2. 代码格式

- 缩进使用 **4 个空格**，禁止 Tab 字符（或遵循项目 `.editorconfig`）。
- 单行字符数 **≤120**。
- 大括号换行遵循 K&R 风格（左大括号不换行）。
- 统一 import 顺序，消除多余空行与尾随空格。
- **禁止代码体内写全限定类名**：类引用一律 `import` 后使用短名。
  - ✅ `import com.yzt.open.rpc.mt.MTOrderServiceWrap;` → 体内 `MTOrderServiceWrap x = ...;`
  - ❌ 体内 `com.yzt.open.rpc.mt.MTOrderServiceWrap x = ...;`
  - 适用范围：变量声明、字段声明、方法参数/返回类型、泛型参数、注解值、cast、`instanceof`。
  - 仅两种例外：(a) 同文件同名类消歧义；(b) 反射 / 字符串 API（`Class.forName("...")` 等）。
- 团队必须共享 IDE 代码风格配置文件，避免 diff 噪音。

## 3. 代码结构

- **结构清晰优先**：代码组织要让读者一眼看出整体结构和逻辑层次。
- **方法短小**：单个方法只做一件事，长度控制在 30 行以内；超出时拆分为语义明确的子方法。
- **层次分明**：高层方法描述"做什么"，低层方法描述"怎么做"；调用链从上到下，抽象层级递减。
- **早返回**：用 guard clause 提前处理异常/边界情况，减少嵌套层级。
- **分段留白**：逻辑段之间用空行分隔，每段完成一个独立步骤；段首可加单行注释概括意图。
- **命名即文档**：变量名、方法名、类名要充分表达意图，减少对注释的依赖。
- **参数精简**：方法参数不超过 4 个；参数过多时封装为对象。
- **单一职责**：每个类/模块只承担一个明确职责，文件不超过 300 行为宜。

## 4. 问题级别定义

| 级别 | 有影响 | 发生概率 | 说明 |
|------|--------|----------|------|
| BLOCKER | 是 | 高 | 阻断问题，必须立即修复 |
| CRITICAL | 是 | 低 | 严重问题，优先修复 |
| MAJOR | 否 | 高 | 主要问题，计划修复 |
| WARNING | 否 | 低 | 警告，建议修复 |
