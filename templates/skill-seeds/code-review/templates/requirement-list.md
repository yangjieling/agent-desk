## 字段约束（最小字段，缺一即报错）

Step 1 校验入参 `requirement_list` 时按此校验。任一字段缺失 → 立即报错并提示本模板路径。

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `ID` | 是 | `R\d{3}` 形式，连续编号 |
| `需求点` | 是 | 一句话主谓宾，≤30 字 |
| `PRD 原文` | 是 | 引文片段；无对应 PRD 描述时填「无」（不是空） |
| `优先级` | 是 | `P0` / `P1` / `P2` |
| `验收点` | 是 | 至少 1 条代码层面**可检验**条件 |
| `备注` | 是 | 无内容时填 `—`（不是空） |

数据库扩展字段用于 Step 4.3 数据库变更扫描。旧版清单缺少这些字段时不阻塞，按 `未知` 处理；若 diff 命中数据库操作，报告中必须提示补充数据库元信息。

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `数据库变更` | 否 | `是` / `否` / `未知`；涉及字段、表、索引、Mapper CRUD、SQL/DDL 时填 `是` |
| `关联表` | 否 | 相关表名列表；无数据库变更填 `-`；无法判断可填 `未知` |
| `PRD 表结构来源` | 否 | 只看 PRD 是否提供表结构，用于物料完整性核对。可填 `PRD §X` / `已附完整 DDL` / `已附结构摘要` / `缺失` / `未知` |
| `审查使用的 schema 来源` | 否 | 用于 D 系列 `confidence` 置信度说明。可填 PRD 章节、项目 SQL/DDL 文件、迁移目录、dev 库 schema、`无` 或 `未知` |

## 数据库物料完整性判定

判定对象是 `PRD 表结构来源` 指向的 PRD 内容，不包括代码库 DDL。即使项目代码库里能找到 DDL，只要 PRD 未提供表结构，物料完整性仍应标缺失。

| 状态 | 判定条件 |
|------|----------|
| ✅ 完整 | 表名、字段名、字段类型、NULL/默认值、主键、唯一键、普通索引、字段语义说明全部齐全 |
| 🟡 部分 | 有表名和字段名，但缺少索引清单、唯一键、NULL 约束、默认值或字段说明中的任一项 |
| ❌ 缺失 | 无任何表结构信息，或只有业务概念描述（如“用户积分表”但没有字段） |

只读接口可不提供完整建表 DDL，但必须提供足以审查 SQL 的结构摘要：字段名、类型、主键、唯一键、索引清单。任一缺失视为 🟡 部分；全部缺失视为 ❌ 缺失。同一需求关联多张表时，取最差状态作为该需求的物料完整性结论。

## 编辑指南（给用户看）

第一次跑出该清单后，若发现拆分不准，可以：

1. **补字段**：PRD 原文里写了但解构漏掉的细节，直接加进对应需求点的"验收点"
2. **改表述**：自动生成的"需求点"措辞不准 → 改成更贴近代码可定位的表述
3. **加遗漏点**：补 `R00N` 新行
4. **删除误拆**：把过细 / 实际不属于本次范围的行删掉
5. **拆分过粗**：把一行拆成多行，ID 重排

修改完成后，把这个文件路径作为 `requirement_list` 参数传回即可复跑。建议在"备注"里记录修正原因，便于追溯。

## 解析规则（给 skill 看）

- 表格头必须出现"ID / 需求点 / PRD 原文 / 优先级 / 验收点 / 备注"6 个核心列（顺序可调，列名严格匹配）
- 数据库扩展列缺失时不阻塞，按 `未知` 补齐内部值；命中数据库操作时必须在报告中提示补充
- 列名前后空格 / 全半角符号被规范化为标准列名
- ID 不允许重复，重复 → 报错
- 优先级 ∉ {P0, P1, P2} → 报错
- 表外其他章节（元信息 / 编辑指南）解析时忽略，不影响入参校验
