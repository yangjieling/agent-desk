# Problem Grading（问题分级判断）

## 任务

判断问题应该走快速通道还是完整流程，确保修复质量与效率的平衡。

---

## 输入

来自输入识别阶段的信息：
- 输入类型
- **Bug 类型**（code-error / logic-deviation）
- 异常详情（如有）
- 问题现象（如有）
- 日志内容（如有）

---

## 执行步骤

### 步骤 1：检查 Bug 类型

**Bug 类型来自输入识别阶段**：
- `logic-deviation`（需求偏差）→ **必须走完整流程**（需要产品确认）
- `code-error`（代码错误）→ 继续后续检查

### 步骤 2：检查问题类型黑名单

以下类型**必须走完整流程**：
- 并发问题（线程安全、死锁、竞态条件）
- 性能问题（慢查询、内存泄漏）
- 安全问题（注入、越权、敏感数据泄露）
- 数据一致性问题
- 涉及支付/资金/库存
- 涉及权限/认证/授权
- 涉及分布式事务
- 涉及跨服务调用
- 影响范围不明确
- 根因不明确

### 步骤 3：检查问题类型白名单

以下类型可以走快速通道：
- 空指针异常
- 参数校验缺失
- 配置错误/配置缺失
- 简单的逻辑判断错误
- 文案错误/UI显示问题
- 简单的类型转换错误

### 步骤 4：评估代码维度

**说明**：此阶段的代码维度评估基于问题类型的初步判断，如无法准确评估，默认走完整流程。

**"处"的定义**：一处改动 = 一个文件中的一个连续代码块

| 条件 | 要求 | 超标判定 |
|-----|------|---------|
| 修改文件数量 | ≤ 3 个不同文件 | 超过 3 个不同文件 → 超标 |
| 单处改动范围 | ≤ 5 行 | 某处改动超过 5 行 → 超标 |
| 涉及核心业务 | 不涉及核心业务逻辑文件 | 涉及核心业务文件 → 超标 |

**核心业务逻辑文件（快速通道禁止修改）**：
- 包含 Payment、Order、Finance、Account 等关键词的服务类
- 包含 Transaction、Settlement、Price 等关键词的业务类
- 权限认证相关类（Security、Auth、Permission）
- 数据一致性相关类（Lock、DistributedTx）

**超标示例**：
- 需要修改 UserService.java + OrderService.java + PaymentService.java → 3 个文件，超标
- 在某个文件中修改了 15 行代码 → 单处超过 5 行，超标
- 修改 OrderService.java 中的支付逻辑 → 涉及核心业务，超标

### 步骤 5：评估影响维度

| 条件 | 要求 |
|-----|------|
| 影响范围 | 仅限当前模块 |
| 业务重要性 | 不涉及核心业务逻辑 |
| 数据一致性 | 不涉及数据一致性问题 |
| 并发场景 | 不涉及并发场景 |

### 步骤 6：做出决策

**快速通道条件**：同时满足
- Bug 类型为 code-error
- 问题类型在白名单
- 代码维度符合要求
- 影响维度符合要求

**否则**：走完整流程

---

## 截止条件

### 成功
- 已完成问题类型判断
- 已做出流程路径决策

### 失败
- 无法判断问题类型
- 信息严重不足且无法补充

---

## 输出

### 快速通道
- 分级结果：简单问题
- 决策依据：符合快速通道条件的原因
- 问题类型：具体问题类型

### 完整流程
- 分级结果：复杂问题
- 决策依据：需要走完整流程的原因
- 问题类型：具体问题类型
- 风险提示：如涉及黑名单类型，说明风险点

**确认闸门**：首次分级结果直接进入对应路径，无需闸门。若后续发生快速通道↔完整流程切换，或 Bug 类型切换，须由 SKILL.md 开 **闸门「流程切换」**（含京 ME）。
