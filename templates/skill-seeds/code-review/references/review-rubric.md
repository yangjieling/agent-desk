# Review Rubric

需求点四态判定标准、"实现风险 vs 未实现"边界、风险等级计算规则。Step 4.1 / Step 5 据此评分。

---

## 一、四态判定标准

每个需求点必须落入以下唯一一态。

### ✅ 已实现

同时满足：

- 主体逻辑、字段、流程在代码中完整覆盖
- 行为与 PRD 描述一致（命名可不同，但语义对齐）
- 异常分支、边界、必填校验等 PRD 已声明的细节都有兜底
- 测试代码若存在，至少能验证主路径（测试缺失不直接降级，但记入备注）

### 🟡 部分实现

主体逻辑有了，但缺至少一项：

- PRD 提到的字段未落库 / 未透出
- PRD 提到的分支条件未覆盖（如"非首次登录跳过验证码"未实现）
- PRD 提到的异常 / 边界 / 必填校验未处理
- 字段范围被收窄（如 PRD 要求 0~100，代码限 0~50）

判定关键：**"够用但不全"**。如果连主路径都跑不通 → 直接归 ❌ 未实现。

### ❌ 未实现

- PRD 明确声明的需求点在 diff 中完全没有对应改动
- 代码中出现了占位符 / TODO / 抛 `UnsupportedOperationException` 等"先放着"标记
- 接口签名有，但函数体为空或仅返回固定值

### ⚠️ 偏离

代码确实做了，但与 PRD 描述不一致。常见模式：

- 字段语义不对（如 PRD 要"商家ID"，代码用了"门店ID"）
- 流程顺序错了（先扣库存再支付 vs 先支付再扣库存）
- 阈值/规则与 PRD 数字不符（PRD 要求最多 5 次，代码限 3 次）
- 接口对接方与 PRD 不一致

⚠️ 偏离比 ❌ 未实现更危险——代码看似工作但行为错。

---

## 二、实现风险 vs 未实现 的边界

容易混淆。判定锚点：**"PRD 是否声明过这件事"**。

| 情形 | 归类 |
|------|------|
| PRD 明确要求"非空校验" → 代码没写 | ❌ 未实现 |
| PRD 没写但需求点是"登录" → 代码对 `phone.trim()` 没做 null 兜底，会 NPE | ⚡ 实现风险（关联到登录需求点） |
| PRD 没写也跟任何需求无关 → 代码 NPE | 🔴 关键代码质量 |
| D 系列数据库规范明确禁止 → SQL / Mapper / DDL 违反 | 📐 数据库规范违规 |
| 团队规范明确禁止 → 代码违反（无论需求） | 📐 规范违规 |

判定顺序：**数据库规范 D 系列 > 团队规范 > 实现风险 > 关键代码质量 > 不报**。具体去重按 `SKILL.md` Step 4.7 的 `(concept, target, fix_action)` 指纹执行。

---

## 三、风险等级（最终报告 P 字段）

取最严重项，按 🔴 → 🟡 → 🟢 顺序判定，命中即停。

| 等级 | 触发条件（任一即生效） |
|------|----------------------|
| 🔴 高 | 任一 ❌ 未实现 / 高危代码硬伤（NPE 主路径、SQL 注入、并发安全、数据丢失、鉴权绕过）/ 确认 P0 规范违规 / 确认 D 系列 P0 / 物料缺失且涉及 DDL、INSERT、UPDATE、DELETE、唯一性约束或状态流转字段 / P0 候选关联且证据链闭合 |
| 🟡 中 | 任一 ⚠️ 偏离 / 🟡 部分实现 / ⚡ 实现风险 / 中等代码硬伤 / P1 规范违规 / 物料缺失但仅涉及只读 SELECT / D 系列 P1 / `🟡 疑似` D 系列 P0/P1 / XDB 超范围数据库改动 / P1 候选关联 |
| 🟢 低 | 全部 ✅ 已实现，仅有 ➕ 超范围或 P2 违规 / 全部主动豁免 |

`🟡 疑似` 不等于确认缺陷。若问题依赖未验证的业务数据分布、上游初始化链路、运行时配置、内部 SDK 行为或线上流量特征，只能作为疑似项进入 🟡 中风险或待确认行动项；不要仅因其"潜在影响可能达到 P0"就把总风险升为 🔴 高。

---

## 四、证据要求

任何状态结论必须附证据：

- `file:line` 精确到行
- 不超过 5 行代码片段
- 多处证据可列多条，但不重复贴整段大代码

无证据 → 不允许下结论，应转为「需人工核对」并在报告中标注。

---

## 五、特殊情形

| 情形 | 处理 |
|------|------|
| PRD 涉及图示/流程图无法直接拆解 | 拆解时标注「需人工核对」，状态留空，报告中提示用户复核 |
| 同一需求点跨多个文件 | 全部列入"关联代码"，整体取最低状态（如有一处 ❌ 则整体 ❌） |
| 需求点彼此依赖（A 未实现导致 B 无法验证） | B 状态置为「依赖待解决」（在备注中说明），不强行判定 |
| 测试代码独立修改 | 不参与四态评分，仅作辅助证据 |
