# Bug 场景分类标准

---

## 一、按问题类型分类

### 1. 逻辑错误（Logic Error）

```yaml
description: 代码逻辑实现与预期不符

常见场景:
  - 条件判断错误：if/else 分支判断条件写反或遗漏
  - 循环逻辑错误：循环条件错误、死循环、循环次数不对
  - 运算错误：计算公式错误、数据类型转换错误
  - 边界处理错误：数组越界、空值未处理
  - 逻辑遗漏：某些场景未覆盖
  
识别特征:
  - 有明确的期望行为和实际行为差异
  - 代码可以正常运行，但结果不符合预期
  - 通常可以通过复现步骤定位

修复策略:
  - 定位具体逻辑分支
  - 分析期望行为
  - 修正逻辑判断
```

### 2. 数据错误（Data Error）

```yaml
description: 数据处理相关问题

常见场景:
  - 数据为空未处理：NullPointerException、空指针访问
  - 数据格式不匹配：类型转换失败、格式解析错误
  - 数据状态不正确：状态机流转错误、脏数据
  - 数据一致性问题：并发更新、事务问题
  - 数据丢失：未正确保存、覆盖写入
  
识别特征:
  - 通常伴随数据相关异常
  - 可能有数据库日志或数据快照辅助分析
  - 特定数据触发，其他数据正常

修复策略:
  - 增加空值判断和默认值处理
  - 增加数据格式校验
  - 修复数据状态逻辑
  - 增加事务控制或并发处理
```

### 3. 配置错误（Config Error）

```yaml
description: 配置相关问题

常见场景:
  - 配置缺失：必要配置项未配置
  - 配置错误：配置值不正确
  - 环境配置不一致：测试环境正常，生产环境异常
  - 配置未生效：配置修改后未重启或未刷新
  - 配置覆盖：多处配置冲突
  
识别特征:
  - 环境差异导致的问题
  - 配置变更后出现
  - 特定环境或节点出现

修复策略:
  - 补充缺失配置
  - 修正错误配置
  - 统一环境配置
  - 增加配置校验
```

### 4. 并发问题（Concurrency Error）

```yaml
description: 多线程/并发相关问题

常见场景:
  - 线程安全问题：共享变量未加锁
  - 资源竞争：多个线程竞争同一资源
  - 死锁：循环等待导致系统挂起
  - 竞态条件：执行顺序依赖导致结果不确定
  - 可见性问题：线程间数据不可见
  
识别特征:
  - 问题时有时无，难以复现
  - 高并发场景下出现
  - 多线程相关日志
  - CPU 使用率异常

修复策略:
  - 增加同步机制（锁、原子类）
  - 使用线程安全的数据结构
  - 避免死锁（统一锁顺序、超时机制）
  - 使用 volatile 保证可见性
```

### 5. 性能问题（Performance Error）

```yaml
description: 性能相关问题

常见场景:
  - 资源泄漏：连接未关闭、内存泄漏
  - 批量处理不当：一次处理过多数据
  - 查询效率低：SQL 未优化、缺少索引
  - 缓存问题：缓存穿透、缓存雪崩
  - 网络超时：连接超时、响应超时
  
识别特征:
  - 响应时间慢
  - 资源占用高
  - 超时错误日志
  - 监控指标异常

修复策略:
  - 优化算法和数据结构
  - 增加缓存
  - 分页/批量处理
  - 增加索引
  - 异步处理
```

### 6. 依赖问题（Dependency Error）

```yaml
description: 外部依赖相关问题

常见场景:
  - 第三方服务异常：外部接口超时、返回错误
  - 接口契约变更：上下游接口不兼容
  - 版本不兼容：依赖版本冲突
  - 依赖不可用：服务宕机、网络不通
  - 依赖配置错误：地址、认证信息错误
  
识别特征:
  - 依赖服务相关错误日志
  - 特定时间点出现
  - 网络/超时相关异常

修复策略:
  - 增加重试和熔断机制
  - 增加降级方案
  - 版本对齐
  - 增加依赖健康检查
```

## 二、按技术层次分类

### 1. 前端层（Frontend）

```yaml
问题类型:
  - UI 渲染错误
  - 交互逻辑错误
  - 数据绑定问题
  - 样式问题
  - 兼容性问题

常见错误:
  - JavaScript 运行时错误
  - CSS 样式冲突
  - 浏览器兼容性
  - 移动端适配问题
```

### 2. 接口层（API）

```yaml
问题类型:
  - 接口参数校验错误
  - 接口路由错误
  - 接口权限问题
  - 接口版本兼容

常见错误:
  - 400 Bad Request
  - 401 Unauthorized
  - 404 Not Found
  - 405 Method Not Allowed
```

### 3. 业务层（Business）

```yaml
问题类型:
  - 业务逻辑错误
  - 状态流转错误
  - 权限校验错误
  - 流程编排错误

常见错误:
  - 业务规则不符合预期
  - 状态机错误
  - 业务异常
```

### 4. 数据层（Data）

```yaml
问题类型:
  - 数据库操作错误
  - 数据一致性问题
  - 数据迁移问题
  - 缓存问题

常见错误:
  - SQLException
  - 数据死锁
  - 数据丢失
  - 缓存穿透
```

### 5. 基础设施层（Infrastructure）

```yaml
问题类型:
  - 服务器问题
  - 网络问题
  - 存储问题
  - 配置中心问题

常见错误:
  - 服务器宕机
  - 网络超时
  - 磁盘满
  - 配置不可用
```

## 三、按影响范围分类

### 1. 致命问题（Fatal）

```yaml
特征:
  - 系统崩溃
  - 核心流程阻断
  - 数据丢失
  - 安全漏洞

示例:
  - 支付系统完全不可用
  - 订单数据丢失
  - 用户敏感信息泄露
```

### 2. 严重问题（Critical）

```yaml
特征:
  - 主要功能不可用
  - 大面积用户受影响
  - 严重影响业务收入

示例:
  - 登录功能失败
  - 查询接口超时
  - 下单流程中断
```

### 3. 一般问题（Normal）

```yaml
特征:
  - 部分功能异常
  - 小范围用户受影响
  - 有临时绕过方案

示例:
  - 个别接口报错
  - 特定场景失败
  - 非核心功能异常
```

### 4. 轻微问题（Minor）

```yaml
特征:
  - 体验问题
  - 边缘场景
  - 影响很小

示例:
  - UI 样式错位
  - 文案错误
  - 提示信息不准确
```

## 四、使用说明

### 分类优先级

1. 首先按**问题类型**分类（逻辑/数据/配置/并发/性能/依赖）
2. 其次按**技术层次**分类（前端/接口/业务/数据/基础设施）
3. 最后按**影响范围**分类（致命/严重/一般/轻微）

### 分类用途

- **问题标准化阶段**：根据用户输入快速识别问题类型
- **根因分析阶段**：辅助根因分析
- **问题分级评估阶段**：辅助问题分级评估
- **修复生成阶段**：选择合适的修复模板
