# Problem Grading Evaluation（问题分级评估）

## 任务

评估问题的严重程度和风险级别，为修复优先级和资源分配提供依据。

---

## 输入

来自根因分析的信息：
- 根因定位
- 影响范围
- 关联问题

---

## 执行步骤

### 步骤 1：评估严重级别

根据影响范围评估：

| 级别 | 判定条件 |
|-----|---------|
| **P0** | 系统崩溃、核心功能不可用、数据丢失、安全漏洞 |
| **P1** | 主要功能受损、影响大量用户、业务流程中断 |
| **P2** | 次要功能异常、影响部分用户、有临时解决方案 |
| **P3** | 体验问题、边界场景、影响很小 |

### 步骤 2：评估风险级别

根据修复难度和影响评估：

| 级别 | 判定条件 |
|-----|---------|
| **高风险** | 涉及核心逻辑、改动范围大、可能引发连锁问题 |
| **中风险** | 涉及重要逻辑、改动适中、需要充分测试 |
| **低风险** | 简单修复、改动范围小、影响可控 |

### 步骤 3：评估发生频率

| 频率 | 判定条件 |
|-----|---------|
| **必现** | 每次都会发生 |
| **偶现** | 特定条件下发生 |
| **罕见** | 极少数情况下发生 |

### 步骤 4：综合评估

结合以上维度给出综合评估：
- 修复优先级
- 建议处理方式
- 注意事项

---

## 截止条件

### 成功
- 已评估严重级别
- 已评估风险级别

### 失败
- 信息不足无法评估

---

## 输出

### 严重级别
- 级别：P0/P1/P2/P3
- 依据：为什么是这个级别
- 影响说明：具体的影响情况

### 风险级别
- 级别：高风险/中风险/低风险
- 依据：为什么是这个风险
- 风险点：主要的风险点是什么

### 发生频率
- 频率：必现/偶现/罕见
- 条件：什么情况下会出现

### 综合评估
- 修复优先级：建议的修复优先级
- 建议处理方式：如何处理更合适
- 注意事项：修复时需要注意什么
